# Accessible narrated tour — requirements, design & tasks

## Problem
Judges and new operators need to understand the UI fast, and the submission must
show genuine accessibility consideration (a scored criterion).

## Requirements
- A step-by-step, game-style walkthrough of every part of the dashboard.
- Each step is usable THREE ways at once: a readable caption, narration audio,
  and a pointing arrow — so it never depends on one sense.
- A reduced-motion option, and graceful behavior when a narration file is absent
  (caption still shows; no error).

## Design
- `datamon/tour.py`: `TourStep` records + `render_tour(st, reduced_motion)`.
  Passing the `streamlit` module in keeps the module unit-testable headless.
- Audio resolves `narration/audio/<step_id>.<ext>`, preferring `.mp3` (recorded
  narration) over `.wav` (a generated cue).
- Narration script authored to the judging criteria lives in `narration/SCRIPT.md`.
- An error cue (`alert_error.wav`, generated by `scripts/make_alert_sound.py`)
  plays on gate/upload failures.
